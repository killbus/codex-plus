# 继承 Goal 基线 — 技术设计

The child copies the source repository snapshot as the goal-only artifact. A
provenance verifier checks the upstream commit checkout, applies the original
patch, and compares an ordered manifest. It separately records known Windows
materialization differences instead of excluding arbitrary files.

The goal-only tree keeps the source behavior (“only UsageLimitExceeded pauses”) so
the inherited contract remains independently testable. The integrated tree applies
`shadow-mind.patch` directly after the old patch and does not override Goal error
handling. Patch-file inspection and a direct apply check prove the two patches have
no Goal-file conflict.

The integrated tree also keeps automatic approval failures inside Guardian's
existing bounded retry loop. The retry decision remains owned by
`guardian/review.rs`, where structured `CodexErrorInfo` is available. Generic rate
limit exhaustion (`ResponseTooManyFailedAttempts`, including HTTP 429) joins the
already-transient connection, stream-disconnect, overload, and 5xx variants. This
does not change the global model-turn retry classifier and does not make explicit
usage/quota exhaustion, valid policy denial, cancellation, or timeout retryable.

Source and test corrections are committed as `fixup!` commits targeting the
historical commit that owns each behavior, then autosquashed with an interactive
rebase. Only after the rewritten source history is final are `shadow-mind.patch`
and `docs/provenance.json` regenerated; those generated bytes are folded into the
owning patch-chain commit. The immutable Goal patch is never rewritten.

The verifier never mutates the source repository and uses temporary worktrees for
all patch applications. Removing the copied tree and patch is a complete rollback.
